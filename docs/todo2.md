@publish-plan.md 计划，开发完了，有几个地方我们还需要改进一下：

# 功能性问题

1. 在点击发布后，弹出发布弹窗，在准备文件阶段，如果点击取消上传，应该取消准备文件的操作，或者如果取消不了，那后续的上传阶段、获取预览链接阶段也应该取消。在上传阶段、获取预览链接阶段不支持取消上传操作，该按钮应该被禁用。现状是，点击取消后，上传弹窗会关闭，但是所有阶段都会进行。
2. 将取消上传按钮改为取消。
3. cdn 链接还是得手动拼接可能靠谱点，可能需要在上传时记录一下 fileName, filePath 之后上传完成每一个文件后，根据 UPLOAD_CONFIG 中的 cdnHost 和记录的 fileName, filePath 拼接出 cdn 链接。而不是现在的直接获取 sdk 回调的 data.url，sdk 回调的 data.url 是一个拼接鉴权的直接访问 s3 的链接，不能直接用。
4. 后端目前已经可以返回预览链接的完整字段了，字段名改为了 shareUrl，前端可以直接使用这个字段来显示预览链接，下面是返回参数示例：
```
{
  "shareId": "503d8d19-84a1-4937-9fa9-9b1d9dda9147",
  "sceneUrl": "../../asserts/ply/xinghewan/scene_mini.json",
  "previewUrl": null,
  "createdAt": "2026-06-25T16:04:44.000Z",
  "shareUrl": "https://localhost:3001/gaussian/share-viewer/?shareId=503d8d19-84a1-4937-9fa9-9b1d9dda9147"
}
```

# UI 及交互问题

1. 点击发布，弹出发布弹窗后，点击确认发布，页面会卡顿很久，确认发布按钮会长时间保持被点击状态，过一会才会取消；然后面板内容换为发布过程内容，此时面板下方会显示发布成功的字段和预览链接的字段，这个时候还没有发布成功，也没有预览链接，所以这两个字段应该在发布的三个阶段都成功后才显示。
2. 在发布过程中，面板对于过程的展示太过简略，在准备文件过程中，只是会显示一个“准备文件...”类似字段，没有过程进度，很容易让用户误认为死机；在上传阶段，“准备文件...”字段似乎消失，然后突然会出现各个上传文件的进度，用户体验也不太好；上传完成后，弹窗立马变为预览链接的分享状态内容，用户想看看上传了哪些文件都没法看，用户体验也不太好。
3. 取消上传后，关闭所有弹窗，发现在“准备文件阶段”会有一个处理场景的小弹窗，类似导出sog包的小弹窗。这个弹窗不应该显示了，因为我们应该在上传过程面板上看这些进度。
4. 我建议：
4.1. 首先解决卡顿问题，按钮 UI 不应该被卡顿。是不是使用异步或者什么手段解决。
4.2. “准备文件阶段”处理场景的小弹窗不应该再显示了，显示了也看不见，而且也不应该使用这个弹窗看进度。
4.3. 在展示上传过程内容面板时，划分三个阶段，类似checkList 的 UI
```
- [ ] 准备文件（下面是准备状态，在该阶段完成后下面的两个状态消失，该阶段状态标记完成）
      [显示准备完成或者在准备的文件名]
      [显示准备进度条]
- [] 上传阶段（下面是上传状态，在该阶段完成后下面的两个状态消失，该阶段状态标记完成；该阶段可以点击“>”展开按钮展开，点击后，按钮变为“【倒三角符号】可以折叠”，实现查看/折叠上传文件的详细信息”）
        - xxx.json
          [xxx.json 上传状态]
        - xxx.webp
          [xxx.json 上传状态]
        ... ...
      [显示上传完成或者在上传的文件名]
      [显示上传的总进度条]
- [] 获取分享链接（下面是准备状态，在该阶段完成后下面的状态消失，该阶段状态标记完成）
     [显示获取进度条]

取消按钮（在准备文件阶段可以点击，其他阶段禁用）
```
4.4. 上述三个阶段全部完成后，应该在三状态下面显示“发布成功！”，接着显示分享链接内容及复制按钮，如下示意：
```
- [x] 准备文件
- [x] 上传阶段 ">（折叠/展开按钮，上传完成后还支持用户可以查看）" 
- [x] 获取分享链接

发布成功！

分享链接：
【xxxxxxx】文本框显示链接

关闭按钮（取消按钮改为关闭按钮，取消禁用状态） 复制链接（此时显示复制链接按钮）
```
5. 尽量使用 pcui 提供的能力、样式、组件，若有不支持的要自己实现那 UI 风格等方面也要要尽量和 pcui 靠近，要统一。
